# Архитектура

```text
ASIC → локальный Stratum-прокси → пул пользователя
                 │
                 └→ локальная веб-панель
```

Предполагаемые компоненты: сетевое ядро, управление конфигурацией и доступом, учет и метрики, веб-API и интерфейс, тестовые имитаторы майнеров и пулов. Начинать с индивидуального соединения к пулу для каждого майнера: агрегация добавляет сложности с extranonce и пока не является требованием MVP.

## Принципы

- Не привязывать ядро к конкретному пулу; сохранять протокольные расширения и проверять совместимость.
- Не блокировать клиентский майнинг из-за недоступности сервиса обновлений или комиссии; точное поведение DevFee описать до реализации.
- Панель доступна локально по умолчанию; не публиковать секреты или учетные данные в журнале.
- При переключении задания и соединения избегать потери шар; корректность подтверждать тестами, а не обещаниями.

## Решения до реализации DevFee

Определить базу 1%, метод распределения работы, совместимость с extranonce и version rolling, период учета, отображение отклонений, поведение при отказах и собственный пул для комиссии. 1% времени или работы не равен гарантированно 1% денежной выплаты.

## Выбор технологий

Предварительно рассмотреть Rust для ядра и отдельный веб-интерфейс. До фиксации стека проверить существующие библиотеки, их лицензии и пригодность для коммерческого распространения.
