# Mining Proxy

Локальный прокси для BTC-майнеров с веб-панелью и прозрачной комиссией разработчика. Доступны экспериментальный прозрачный TCP-режим и активный Stratum V1 маршрутизатор для лабораторных испытаний.

Клиент сможет самостоятельно указать совместимый пул и резервные адреса. ViaBTC — один из возможных пулов для проверки, а не обязательное условие.

## Лабораторный прототип

В Windows для просмотра можно дважды нажать `scripts/preview-dashboard.cmd`, оставить открывшееся окно и перейти в Chrome по адресу `http://127.0.0.1:18771/`. Это локальный тест без реального пула и майнеров; для остановки нажмите Ctrl+C в окне. Если порты заняты, скрипт не сможет запуститься.

Требуется Python 3.10 или новее. Установите зависимости: `python -m pip install -r requirements.txt`. В отдельном тестовом окружении:

```sh
python launch.py --pool-host 127.0.0.1 --pool-port 4444 --listen-port 3333
python -m unittest discover -s tests -v
```

Прототип открывает отдельное TCP-соединение к указанному адресу для каждого клиента и передает байты без изменений. `--tls` включает проверку TLS-сертификата пула. По умолчанию слушает только localhost. При обрыве одной стороны сеанс закрывается; переподключение выполняет клиент.

При TCP half-close со стороны майнера прокси передаёт EOF пулу и ждёт финальные ответы до трёх секунд. Для исходящего TLS такая передача EOF недоступна; совместимость и поведение настоящих майнеров ещё не проверены.

Локальная панель «Контур» доступна на `http://127.0.0.1:8080/`; порт меняется через `--dashboard-port`. Название рабочее. Панель показывает сводку, активные сеансы, настроенные пулы и диагностику; поиск и фильтр работают по текущим соединениям. Глобальные диагностические счётчики сбрасываются после перезапуска; история воркеров сохраняется отдельно. Счётчики приблизительны: в прозрачном режиме они определяются пассивным наблюдением сообщений, в активном — сопоставленными ответами пула. Для активного соединения показывается последнее успешно авторизованное имя воркера. Пароли не сохраняются в диагностике и не выводятся. Без KONTUR_ADMIN_TOKEN доступно локальное чтение; при заданном токене нужен вход администратора или Observer Link.

Язык панели по умолчанию — английский; переключатель в верхней панели предлагает также русский и упрощённый китайский. Выбор хранится в браузере; если браузер запрещает локальное хранилище, он действует до закрытия страницы.

Причина закрытия соединения — наблюдаемая сторона первого завершившегося потока, а не доказанная первопричина проблемы. Счётчики ожидающих ответов и несопоставленных шар имеют разные значения и не равны подтверждённым потерям.

Состояние «Connected» в списке означает установленное TCP/TLS-соединение с пулом; оно само по себе не подтверждает авторизацию или фактическую добычу.

Среднее время ответа на шару измеряется от её отправки прокси до однозначно сопоставленного ответа пула и включает обработку и очереди. Это не чистый сетевой ping; данные живут только до перезапуска.

Кнопка экспорта скачивает диагностическую JSON-сводку из памяти процесса с именами активных воркеров. В прозрачном режиме сложность и DevFee недоступны (`null`); активный режим показывает подтверждённую пулами сложность. Это не финансовый отчёт. Не передавайте файл посторонним без проверки содержимого.

Панель также считает наблюдаемые команды `client.reconnect` от пула: они могут направить майнер в обход прокси. Прототип **не блокирует** эти команды; счётчик не является полной защитой от перенаправления.

Опционально `--backup-host HOST --backup-port PORT` задаёт резервный адрес **только на этапе установки соединения**, если основной адрес недоступен. Авторизация и шары не проверяются для решения о переключении. После обрыва действующего сеанса требуется переподключение майнера. Резервный адрес получает те же данные авторизации, что основной, и должен их поддерживать. Опция `--tls` применяется к обоим адресам.

Лимит соединений задается `--max-connections` (по умолчанию 512), тайм-аут каждого подключения к пулу — `--connect-timeout` в секундах (по умолчанию 10). На системах с `RLIMIT_NOFILE` программа предупреждает, если мягкий лимит ниже приблизительных 2 сокетов на сеанс плюс 64 дескриптора запаса. Это оценка, не гарантия производительности; системные настройки не меняются автоматически.

Для закрытия сеансов без трафика в обоих направлениях можно задать `--idle-timeout` в секундах. По умолчанию он выключен (`0`): слишком короткое значение может оборвать нормально работающие майнеры или пулы, поэтому устанавливать его следует после измерений. Тайм-аут начинает работать после подключения к пулу и не заменяет ограничение времени установки соединения.

Чтобы ограничить входящие соединения майнеров по IP-сети, укажите `--allow-cidr 192.168.10.0/24`; параметр можно повторить для нескольких подсетей. Для адреса прослушивания вне loopback обязательна сеть `--allow-cidr` либо явное разрешение всех адресов `--allow-any-miner`. При стандартном localhost без этих параметров локальные адреса не фильтруются. IP-фильтр не является аутентификацией и не защищает от вредоносного устройства внутри разрешённой сети; прокси всё ещё экспериментальный.

Прототип проверяет очевидные подключения к собственному слушающему адресу, чтобы уменьшить риск сетевой петли. Проверка не обнаруживает все петли через NAT, другие прокси и изменение DNS: адреса нужно проверять при настройке.

Активный DevFee реализован экспериментально и не проверен на реальном оборудовании. Не открывайте прототип в интернет и не подключайте к рабочей ферме.

В `lab/` находится упрощённый тестовый пул. Он проверяет SHA-256d шары на искусственном задании, но не реализует полный протокол и не является настоящим пулом. Сквозная проверка запускается общей командой тестирования выше.

Для локальной оценки подключения большого числа клиентов: `python -m lab.load_test --clients 400 --ramp-ms 5` (для одновременного старта `--ramp-ms 0`). Стенд использует только локальный echo-сервер, выводит число успехов/ошибок и задержки соединения. Это не испытание реального пула, майнинга, пропускной способности фермы или устойчивости при длительной работе.


## Экспериментальный активный маршрутизатор

Флаг `--active-router` включает обработку Stratum V1; без флага работает прежний прозрачный TCP-режим. Для тестовой комиссии необходимо явно задать `--devfee-host`, `--devfee-port` и `--devfee-worker`; пароль берётся из KONTUR_DEVFEE_PASSWORD (по умолчанию x). Флаг --devfee-password удалён; секреты не следует передавать в аргументах процесса. Флаг `--validate-pow` включает локальную проверку SHA-256d. Значение `--fee-min-work` задаёт минимальный объём принятой сложности между окнами комиссии. Для устройств без подтверждения extranonce предусмотрено переподключение, минимальная продолжительность пользовательского окна задаётся `--reconnect-min-seconds` (по умолчанию 5940 секунд).

Маршрутизатор хранит задания и привязывает каждое к исходному соединению и его extranonce; поддерживающему майнеру при смене пула посылаются set_extranonce, set_difficulty и новое задание. Счётчик комиссии общий для процесса, живёт в памяти и сбрасывается при перезапуске. Доля 1% является целью по сложности однозначно принятых шар и может отклоняться на коротких интервалах и при недоступности пула комиссии; она не гарантирует точную долю выплат. Хешрейт в панели оценивается по принятой сложности за измеренный интервал, на коротких промежутках он нестабилен.

Ограничения: синтетические испытания не подтверждают совместимость с конкретными прошивками или F2Pool, Poolin, ViaBTC и AntPool. В активном режиме не реализованы `--idle-timeout`, полноценный half-close и динамическое изменение маски version rolling (при смене маски сессия закрывается). История заданий и дубликатов ограничена; старый пул может отклонить устаревшую шару. Глобальная бухгалтерия DevFee сбрасывается после перезапуска; история воркеров сохраняется независимо. Резервный пул должен принимать те же реквизиты; TLS применяется ко всем исходящим соединениям. Перед рабочей фермой необходимы тесты реальных устройств, пулов, отказов, нагрузки и независимый аудит.

## Сетевое усиление пилота

Долгий аптайм: DevFee-подключения разнесены случайной задержкой 0–180 секунд и общим интервалом 250 мс; TTL заданий — 15 минут, GC — раз в минуту. CLI и API принимают `stratum+ssl://host:port`, сохраняя проверку сертификата; для собственного CA есть `--tls-ca-file`. Подробности, ограничения и пример запуска — в [обновлении стабильности](long-term-stability.md).

В активном режиме потоковый декодер принимает фрагментированные и склеенные JSON без обязательного перевода строки. Лимит объекта ASIC — 4096 байт (`--max-miner-message`), пула — 65536 байт. Мусорные данные отбрасываются до подключения к пулу. `--handshake-timeout 30` ограничивает авторизацию, `--miner-timeout 600` закрывает молчащий ASIC независимо от уведомлений пула; TCP Keepalive включается отдельно. Vardiff сохраняет точную сложность каждого задания, а запись заданий и переключение extranonce синхронизированы одним lock. Условия, метрики и ограничения описаны в [сетевом аудите](network-hardening.md).

## План развития и обязательная комиссия

Первый этап: активный Stratum-маршрутизатор, независимый TCP-канал DevFee, привязка заданий к сессии и монотонный Watchdog. Режим включается явно: `--active-router --require-devfee --fee-grace-seconds 180` вместе с полными реквизитами DevFee. Отсчёт здоровья DevFee начинается после успешной авторизации на User Pool и запланированного допуска первого DevFee-подключения через Jitter/Gate: неавторизованный клиент не может запустить глобальную блокировку, а намеренная задержка не считается отказом пула. Повторные попытки не сбрасывают отсчёт. После превышения порога недоступности либо периода после отказа шары без последующего подтверждения все активные сессии закрываются; новые блокируются до перезапуска. Тайм-аут отправки шары закрывает неисправный канал. Простаивающий TCP-канал без обмена не доказывает, что пул способен принимать шары. Watchdog проверяет доступность канала каждые 250 мс или чаще при коротком пороге. Он не создаёт искусственные шары и не гарантирует доступность самого пула.

Второй этап: per-worker история с ограничением памяти и окнами 15m/1h/24h, SSE с ограничением числа подписчиков, экспорт и отдельные read-only токены с отзывом. Третий этап: аутентифицированный POST API конфигурации, проверка маршрутов и атомарное применение; затем Kick и IP Blacklist с аудитом действий. Четвёртый этап: журнал переключений и открытый расчёт задолженности по принятой сложности. Изменяющий настройки API нельзя добавлять без аутентификации, CSRF-защиты и ограничений запросов.

FeeHealth использует типизированные поля и методы и monotonic clock; проверка срока вызывается также при выдаче заданий, переключении и отправке шар. Это временное ограничение исполнения, не криптографическая защита от владельца исходников. Cython/Nuitka и закрытая сборка потребуют отдельного испытания упаковки; компиляция сама по себе не делает код неотключаемым. SSE, детализированная статистика, Observer Link и защищённые управляющие POST-эндпоинты реализованы экспериментально.


## Воркеры и обновления в реальном времени

`WorkerRegistry` связывает историю с точным именем воркера и нормализованным IP. Несколько соединений с одинаковым именем и IP объединяются: это не надёжный идентификатор физического ASIC. После отключения строка остаётся Offline; переподключение в пределах сохранённой истории возвращает тот же ID и счётчики. Хранятся до 512 строк, отключённые удаляются спустя 24 часа; при нехватке места сначала вытесняются отключённые строки. Если все строки заняты активными воркерами, новые наблюдения пропускаются и панель показывает предупреждение. История сохраняется в локальный checkpoint; ограничения восстановления описаны ниже.

В активном режиме окна 15m/1h/24h вычисляются из сложности принятых пулом шар: `Hashrate = Accepted Difficulty × 2^32 / Measured Seconds`. Используются минутные корзины: границы окон округлены до минут. Неполное окно отмечено звёздочкой и содержит измеренную продолжительность в подсказке. Работа DevFee включается в общий хешрейт устройства, но отражается отдельно в глобальном ledger. В прозрачном режиме сложность не привязывается к заданиям, поэтому хешрейт отсутствует. Accepted/Rejected/Stale доступны по однозначным ответам пула; Stale — подмножество Rejected с кодом ошибки 21. Классификация зависит от протокола конкретного пула. Локальные отказы и неизвестные результаты учитываются отдельно.

Среднее время ответа пула включает очередь и обработку, это не чистый сетевой ping. Сетевой Ping ASIC → Proxy пока не измеряется и передаётся как `null`; панель показывает отдельную метрику notify → первая принятая шара (EMA). Статусы Online/Offline означают наличие авторизованного соединения, а не доказательство исправности чипов.

`GET /api/stream` отправляет SSE-снимок раз в секунду; `GET /api/snapshot` даёт тот же снимок для резервного опроса, `GET /api/workers` — историю воркеров. Протокольные поля и пароли не входят в SSE. Разрешено до 8 подписчиков, очередь каждого содержит только последнее состояние, тайм-аут записи — 3 секунды. Размер SSE-снимка ограничен 2 МиБ; при ошибке фронтенд сохраняет старые данные и использует резервный опрос. Поток передаёт текущее состояние, не воспроизводит пропущенные события.

DevFee Ledger показывает расчётный долг по сложности и последние 500 подтверждённых отправкой заданий назначений/переключений сессий. В таблице видны последние 50. Это журнал из памяти, а не неизменяемый аудит или доказательство выплаты. SSE обслуживается локальной панелью; при заданном административном токене он защищён авторизацией. Observer Link даёт отдельный доступ только для чтения. Не публикуйте локальный API через внешний туннель без отдельного контроля доступа.

## Административный API и ссылки наблюдателя

Перед запуском задайте переменную окружения `KONTUR_ADMIN_TOKEN` со случайным секретом длиной не менее 32 символов. При заданном секрете обычные API требуют заголовок `Authorization: Bearer <секрет>`. Секрет администратора не сохраняется в JSON. Без него остаётся прежний локальный режим чтения, изменяющие запросы запрещены. Кнопка Sign in открывает форму входа. Токен хранится в Session Storage текущей вкладки и передаётся в Authorization, включая SSE через fetch-stream. Sign out очищает токены и перезагружает страницу без старого приватного снимка.

Реализованы POST `/api/observer-links` с телом `{}` (ссылка чтения на один час), POST `/api/workers/kick` с `session_id` или `worker` (имя отключает все совпавшие текущие сессии), POST `/api/blacklist` с массивом `blacklist` (замена до 256 IP/CIDR). GET `/api/blacklist` возвращает текущий список. Observer-токены допускаются только к снимкам, воркерам, метрикам и SSE; прочие API, POST и DELETE запрещены. Для браузера используется фрагмент `#observer=...`; UI передаёт токен в Authorization. Совместимый query-параметр observer всё ещё принимается API: при его ручном использовании не записывайте URL в access logs. Панель скрывает журнал переключений, пулы и экспорт аудита в режиме наблюдения; сервер также исключает журнал, конфигурацию и список сессий из снимка наблюдателя. Токен продолжает открывать данные воркеров, включая IP: передавайте его только доверенному получателю.

Blacklist и хеши Observer-токенов записываются атомарно в `state/control.json` (путь задаётся `--control-state`), загружаются до открытия слушателя. При ошибке записи новое состояние не применяется. Файл предназначен для одного процесса; каталог должен быть доступен только владельцу сервиса. Blacklist проверяется до создания Stratum-сессии; добавление не отключает уже существующие соединения — для этого используйте Kick. Это прикладной фильтр принятых TCP-соединений, не защита от перегрузки сети SYN-трафиком. Установлен лимит 30 административных изменений в минуту. Некорректный или повреждённый файл состояния останавливает запуск и не перезаписывается автоматически.

Состояние управления и история воркеров сохраняются отдельно; детали ниже.


## История воркеров, EMA и смена пулов

`--history-file` задаёт файл истории (по умолчанию `state/history.json`; пустая строка отключает сохранение). Checkpoint выполняется каждые 60 секунд и после завершения сессий при корректной остановке. Запись идёт в отдельном потоке через временный файл, fsync и атомарную замену; поколение checkpoint защищает от запоздалой записи отменённого фонового задания. Сохраняются Accepted/Rejected/Stale/Unknown, локальные отказы, окна сложности 15m/1h/24h, среднее время ответа пула и EMA первой шары. После загрузки все воркеры Offline до повторной авторизации. Времена сохраняются относительно UTC и переводятся на monotonic-часы нового процесса, учитывая простой. При выключении питания или принудительном убийстве процесса возможна потеря данных с последнего checkpoint. Повреждённый файл не перезаписывается автоматически: запуск прекращается.

Глобальные диагностические счётчики и финансовая цель DevFee остаются привязанными к текущему процессу; восстановленная история воркеров может содержать большие счётчики, чем сводка с момента запуска. Переход системных часов далеко назад может потребовать восстановления из корректного checkpoint. Формат рассчитан на один процесс, максимум 512 воркеров и 1440 минутных корзин на воркер.

Для каждого выданного job_id фиксируется время постановки mining.notify в отправку. По первой принятой пулом шаре каждого воркера для этого задания вычисляется разница до момента обработки mining.submit; время ответа пула в эту разницу не включается. EMA использует alpha=0.2 и обновляется один раз на задание/воркер. Показатель включает вычисление PoW, локальные очереди и сеть и **не является TCP RTT**. В UI он называется First Share EMA; в API это notify_to_first_share_ema_ms и notify_to_first_share_samples. В прозрачном режиме такого измерения нет.

GET `/api/config` возвращает администратору User Pool и DevFee Pool без паролей. POST `/api/config` принимает user_pool/devfee_pool: host, port, worker, password; devfee_pool=null выключает опциональную комиссию, но запрещён при --require-devfee. Пустое имя User Pool означает передачу исходных реквизитов ASIC; указанное имя переопределяет пользователя и пароль на апстриме. Пропущенный password сохраняет прежнее значение, явная пустая строка задаёт пустой пароль. UI оставляет password пустым при загрузке и не отправляет его без изменения.

Перед применением проверяются схема, петля на собственный слушатель и доступность TCP/TLS целевых пулов (до 4 секунд на пул). Это не проверка учётной записи и не гарантия дальнейшей доступности пула. Затем конфиг атомарно сохраняется в control.json и применяется одной операцией. Параметр generation защищает от перезаписи устаревшей формы. В конфиге пароли теперь сохраняются как Fernet-шифротекст с ключом KONTUR_SECRETS_KEY либо ссылки на ENV. Каталог state и отдельный ключ должны быть закрыты от других пользователей и публикации. Миграция старых plaintext-конфигов описана в docs/pilot-prep.md. Git игнорирует каталог; это не ограничивает внешнюю синхронизацию файлов. На POSIX временные файлы создаются с правами владельца, на Windows следует проверить ACL каталога.

Новые сессии сразу используют новое поколение настроек. По умолчанию активным сессиям отправляется client.reconnect и закрывается сокет: майнер должен переподключиться с обновлённым extranonce, поэтому это **не сохранение TCP-сессии**. Можно передать reconnect=false: старые сессии продолжат работу с зафиксированными адресами и реквизитами. Настройки восстанавливаются из control.json при старте и имеют приоритет над начальными адресами CLI. Порт слушателя и резервный адрес в этом API не меняются. Watchdog, если уже заблокировал обслуживание, остаётся заблокированным до перезапуска.

В таблице воркеров Kick адресуется по worker_id (имя + IP) и закрывает все его сессии. Ban IP атомарно добавляет адрес в Blacklist, блокируя новые соединения; существующие отключаются отдельной кнопкой Kick. Во вкладке Routes доступны формы пулов и генерация Observer Link, ниже — Blacklist с удалением адресов. В режиме наблюдателя управляющие формы, действия и журнал скрыты; backend независимо запрещает запись.


## Security Hardening & Pilot Prep

Реализованы ENV/dotenv (с приоритетом серверного ENV), шифрование паролей конфигурации, редактирование секретов перед очередью логгера, ротация JSON-логов и cooperative SIGINT/SIGTERM. `build_ext.py` готовит отдельный каталог бинарных runtime-модулей без исходников ядра. Подробные команды, зависимости, границы защиты и план проверки на реальном оборудовании — в [инструкции пилота](pilot-prep.md). Бинарная сборка и синтетические тесты не подтверждают готовность к реальной ферме.
