# Дальнейшая работа

1. Протокольный стенд: корректные задания SHA-256 и проверка шар, разные сложности и варианты ответов.
2. Ядро: обнаружение разрывов и тайм-аутов, политики подключения, раздельные настройки пулов, тесты TLS и отказов; проверить на Linux и реальных устройствах.
3. Диагностика: подтверждённые пулом данные, состояние каждого воркера без раскрытия секретов, история и причина потерь. Сравнение с прямым подключением с указанием ограничений измерения.
4. Панель: защищённая настройка, пользователи и роли, аудит изменений; хранение настроек, восстановление и обновления.
5. DevFee: проработка и испытания согласно `devfee.md`, без обещания точного процента денежных выплат.
6. Контролируемый пилот, тестирование безопасности, проверка лицензий и юридических условий, документация, поддержка и только затем публичный запуск.

Текущий Python-прототип предназначен для проверки архитектуры. Решение об окончательном языке и реализации ядра принимается после испытаний; производственная готовность не подтверждена.
