# Безопасность: границы и открытые задачи

## Что защищаем

Доступность майнинга, корректность направлений заданий и выплат, учётные данные пулов, настройки, доступ к панели и обновления. Возможные нарушители: посторонний в сети фермы, сайт в браузере оператора, скомпрометированный пул/прокси, локальный пользователь, атакующий сервер обновлений. Не все эти угрозы пока устранены.

## Уже есть в прототипе

- Панель слушает только `127.0.0.1`, запросы ограничены ожидаемым Host, есть CSP. Это не защита от других локальных пользователей или вредоносных программ на том же компьютере.
- TLS к пулу опционален; при включении проверяются сертификат и имя сервера. Без TLS трафик виден и может изменяться в сети.
- Лимит соединений, ограничение наблюдаемого сообщения и числа ожидаемых идентификаторов; простая проверка очевидных петель; пароли не выводятся в панель или журнал.
- `--allow-cidr` ограничивает адреса источников майнеров до подключения к пулу. Для прослушивания вне loopback требуется разрешённая сеть либо явный `--allow-any-miner`; на loopback без фильтра доступны все локальные клиенты. NAT и доверенные сети влияют на то, какой IP видит прокси. Это не замена авторизации.

## Не закрытые риски до выпуска

1. Нет аутентификации или ролей, аудита изменений, защищённого удалённого управления и защиты API для записи. Не открывать панель наружу и не добавлять изменение настроек до реализации.
2. Прозрачный TCP-прокси передаёт сообщения пула как есть. Например, команда `client.reconnect` может привести к обходу прокси; её наблюдаемый счётчик отображается в панели, но перенаправление не блокируется. Наблюдение приблизительно и не обнаруживает все способы обхода. Нужны политика допустимых перенаправлений, проверки и совместимые тесты до управляемого режима.
3. Проверка петель не покрывает NAT, другие промежуточные узлы и изменение DNS. Не гарантирует отсутствие DNS rebinding или перенаправления на внутренние сервисы.
4. Не проверены устойчивость к злонамеренному потоку, исчерпанию памяти/дескрипторов, медленным клиентам, массовым переподключениям и длительным отказам в реальных условиях.
5. Нет модели секретов для будущего хранения настроек, проверки обновлений/подписей, безопасной установки или независимого аудита.
6. Соединение с майнером по обычному TCP не защищает сеть между ASIC и прокси. Совместимость TLS на входе зависит от оборудования и должна проверяться отдельно.

## Правила для следующих изменений

Меньше привилегий, закрытые по умолчанию сетевые интерфейсы, минимизация секретов, ограниченные ресурсы, проверка сертификатов, тесты отказов и безопасности для каждого изменения сетевой логики. Ведение адресов/учётных данных и любые переключения — только с согласованным поведением и защитой от ошибок. Логи не должны содержать пароли, ключи или полные сообщения авторизации.
